## 1. 产品概述

### 1.1 产品定位

AI 数字人导游是一款面向景区、博物馆、主题乐园等场景的**智能导览系统**。系统以 **AI 数字人** 为核心交互载体，通过 Android 客户端为用户提供自然语言对话式的导游讲解服务，并叠加 **AI 个性化路线推荐**，让游客获得"随身 AI 导游 + 智能游览规划"的沉浸式体验。

### 1.2 核心价值

| 维度 | 说明 |
| --- | --- |
| **沉浸式交互** | AI 数字人口型同步（H.264 实时视频流）、实时语音合成，提供"面对面"讲解体验 |
| **多模态输入** | 支持文本、语音（NLS 实时转写 + 实时字幕）、拍照（VL 多模态识别）等交互方式 |
| **知识驱动** | 基于 RAG 技术，将景区资料文档转化为可检索的知识库，确保回答准确有据 |
| **智能规划** | AI 依据用户偏好从知识库结构化生成游览路线，前端以"灵动岛数轴"展示，结合 GPS 自动判定到达 |
| **智能化管理** | 管理员端提供游客情感分析、热门问题排行、AI 服务建议等数据驾驶舱 |
| **可扩展架构** | 算力分离部署，AI 推理服务独立伸缩，支持多景区横向扩展 |

### 1.3 用户角色

| 角色 | 职责 |
| --- | --- |
| **游客（C 端用户）** | 浏览景点、与 AI 数字人导游对话、生成并跟随个性化路线、查看与评价旅游历史 |
| **景区管理员（B 端用户）** | 管理景点信息、上传知识文档、配置数字人形象与音色、查看数据统计分析 |

### 1.4 终端形态

- **前端**：Android 原生应用（Java，View Binding，MVVM；微信式聊天界面 + 数字人视频渲染 + 灵动岛路线数轴）
- **后端 API**：Spring Boot RESTful + WebSocket 服务
- **管理后台**：集成于 Android 管理端

### 3.2 游客端功能详述

#### 3.2.1 用户认证

- **注册**：账号 4-16 位字母/数字/下划线，密码 6-20 位，昵称 1-20 字符
- **登录**：返回 JWT Token（HS384 签名）+ 用户雪花 ID
- **鉴权**：所有非登录/注册接口通过 `UserJwtInterceptor` 拦截，Token 存 Redis（7 天过期，剩余 < 24h 自动续期）
- **上下文**：`UserContext`（ThreadLocal）在请求生命周期内持有用户 ID

#### 3.2.2 AI 导游对话

核心交互入口，通过 WebSocket 长连接实现**实时双向通信**。一条 WS 连接同时承载：对话、语音、视频、路线四类业务。

```
客户端 ──WebSocket──► Java 后端 ──WebSocket──► CosyVoice (TTS)
                       │    ▲                        │
                       │    ├── Redis (向量检索+画像) │ PCM
                       │    ├── DashScope (LLM/VL)    ▼
                       │    ├── 阿里云 NLS (语音识别)  MuseTalk (数字人 H.264)
                       │    └── MySQL (聊天记忆)
```

**会话标识（v2 变更）**：每次建立 WS 连接生成一个全新的 `conversationId = UUID`（`ChatSessionContext` 构造时 `UUID.randomUUID()`）。这使**同一用户在同一景点可发生多次互不串扰的独立对话**，并作为聊天记忆、旅游历史、体验分析的关联键。

**消息类型矩阵：**

| type | 方向 | 载体 | 说明 |
| --- | --- | --- | --- |
| `text` | 客户端→后端 | Text (JSON) | 文本输入 |
| `micOn`/`micOff` | 客户端→后端 | Text (JSON) | 麦克风开关（创建/停止 NLS 识别器） |
| `photo` | 客户端→后端 | Text (JSON, Base64) | 拍照上传（供下一轮 VL 模型分析） |
| `camera` | 客户端→后端 | Text (JSON) | 摄像头开关（`status:"off"` 清除待处理图片） |
| `interrupt` | 客户端→后端 | Text (JSON) | 主动打断数字人（停 TTS + MuseTalk） |
| `routeGenerate`/`routeArrive`/`routeClose` | 客户端→后端 | Text (JSON) | 路线推荐控制（见 3.2.5） |
| `ping`/`pong` | 双向 | Text (JSON) | 心跳检测 |
| `allDone` | 后端→客户端 | Text (JSON) | 会话初始化完成（MuseTalk + CosyVoice 就绪） |
| `ready` | 后端→客户端 | Text (JSON) | 数字人 avatar 准备就绪 |
| `speechStarted` | 后端→客户端 | Text (JSON) | NLS 检测到一句话开始 |
| `interimText` | 后端→客户端 | Text (JSON) | NLS 中间识别结果（实时字幕） |
| `userInput` | 后端→客户端 | Text (JSON) | NLS 一句话最终识别文本 |
| `aiOutput` | 后端→客户端 | Text (JSON) | AI 文本回复（按标点逐句推送） |
| `responseDone` | 后端→客户端 | Text (JSON) | 回复完成通知 |
| `done` | 后端→客户端 | Text (JSON) | 单句视频生成完毕 |
| `routeTimeline`/`routeUpdate`/`routeClosed`/`routeError` | 后端→客户端 | Text (JSON) | 路线推荐结果（见 3.2.5） |
| `error`/`connectionError` | 后端→客户端 | Text (JSON) | 错误通知 |
| 音频帧（首字节 `0x01`） | 后端→客户端 | Binary | TTS 音频：`0x01` + sentenceId(2B) + ptsMs(4B) + PCM (16kHz s16le mono)，共 7 字节 header |
| 视频帧（首字节 `0x03`） | 后端→客户端 | Binary | 数字人 H.264：`0x03` + sentenceId(2B) + ptsMs(4B) + keyFrame(1B) + H.264 AU，共 8 字节 header |
| 裸 PCM | 客户端→后端 | Binary | 麦克风采集音频（送 NLS 转写） |

#### 3.2.3 景点浏览

- 基于地理位置的游标分页（按距离排序），支持关键词/类型筛选
- 返回景点 ID、名称、封面图、类型、距离
- 用户点击景点进入 WebSocket 对话（连接参数：`token` + `attractionId`）

#### 3.2.4 旅游历史与评价

- 游标分页展示历史对话记录，支持关键词搜索和类型筛选
- 支持单条删除、评分评价（1-5 分 + 文字反馈）
- 每次 WS 连接建立时自动生成一条旅游历史记录（通过 RabbitMQ 异步落库，并创建待评价记录）

#### 3.2.5 AI 路线推荐（灵动岛数轴）★ v2 新增

依据用户个性化偏好，由 AI 从知识库文档中**结构化输出一串有序地标**，前端以"灵动岛"数轴形式展示（含 未到达/进行中/已到达 三态）。

- **承载通道**：复用数字人对话的同一条 WebSocket（`/chat`），仅在对话页存在；**路线生命周期跟随 WS 连接，断开即清理**。
- **坐标系**：地标坐标由后端调用高德 Web 服务预解析，统一返回 **GCJ-02（火星坐标）**；前端定位与到达判定**必须统一使用高德坐标系**，切勿混用系统原生 GPS（WGS-84），否则有数十~数百米偏移。
- **到达判定**：前端用高德定位 + 地标坐标做距离检测，判定到达后通过 `routeArrive` 回报后端持久化并前移指针；保留**手动点选兜底**（室内/密集地标 GPS 不可靠时）。
- **降级**：未配置高德 Key / 配额超限 / 某地标解析失败时，对应节点 `resolved=false`、坐标为空，路线仍正常下发，前端回退为按地标名定位。
- **REST 恢复**：刷新/重连后通过 `GET /users/route/current?attractionId=` 恢复当前激活路线。

**交互消息：**

| 方向 | type | 载荷 | 说明 |
| --- | --- | --- | --- |
| 入站 | `routeGenerate` | 无 | 触发生成个性化路线（异步） |
| 入站 | `routeArrive` | `stopIndex` | 上报某节点已到达，前移当前指针 |
| 入站 | `routeClose` | 无 | 关闭并清除当前路线 |
| 出站 | `routeTimeline` | `data: RoutePlanVO` | 路线生成成功，下发完整数轴 |
| 出站 | `routeUpdate` | `data: RoutePlanVO` | 节点到达后下发更新后的数轴 |
| 出站 | `routeClosed` | 无 | 路线已关闭 |
| 出站 | `routeError` | `text` | 无资料 / 生成失败 / 无可更新路线 |

### 3.3 管理员端功能详述

#### 3.3.1 景点管理

- 景点名称、封面图、类型（主题乐园 / 博物馆与展馆 / 自然公园 / 风景名胜与休闲度假 / 历史文化 / 古镇水乡 / 动植物园与水族馆 / 现代地标）

#### 3.3.2 知识文档管理

```
管理员上传文件 → OSS 存储 → RabbitMQ (doc.convert.request)
    → markitdown-worker 下载+解析 → Markdown 文本
    → RabbitMQ (doc.convert.result) → Java 后端
    → TokenTextSplitter (800 字符块, 表格保护) → Redis VectorStore
    → MySQL 元数据记录

- 支持格式：`.doc`、`.docx`、`.pdf`
- 上传后返回 `taskId`，前端每 2 秒轮询解析状态（PROCESSING / SUCCESS / FAILED）
- 解析完成的文档自动向量化存入 Redis，用于 RAG 检索；单景点最多管理若干文档

#### 3.3.3 数字人管理

- 配置景点对应的数字人肖像图与音色（OSS 地址）
- 上传驱动视频（`.mp4`），后端通过 RabbitMQ 通知 MuseTalk **预加载头像**（前端轮询 preload-status）
- 支持用自定义文本生成**测试视频**预览（`video.test.queue` → SoVITS 合成 + MuseTalk 离线出帧）
- 支持新增、编辑、删除

## 4. 核心技术流程

### 4.1 AI 导游对话全链路

```
                    Android                      Java 后端                      AI 服务
                       │                            │                             │
  ── 建立连接 ──►  WS /ai-project/chat?token=&attractionId=                       │
                       │                            │                             │
                       │                    1) 握手 JWT 鉴权 (query/Header)        │
                       │                    2) 注册 ChatSessionContext            │
                       │                       (conversationId = UUID)           │
                       │                    3) 缓存用户画像 → Redis               │
                       │                    4) 发送旅游历史 + 待评价 → RabbitMQ    │
                       │                    5) 连接 MuseTalk WS ──────────►  init + 预加载头像
                       │                    6) 连接 CosyVoice WS ─────────►  init + 加载音色
                       │  ◄── allDone ────          │                             │
                       │                            │                             │
  ── 文本输入 ──►  {"type":"text","text":"..."}     │                             │
                       │                    1) 令牌桶限流检查                     │
                       │                    2) DynamicPromptService 拼装提示词     │
                       │                       • 用户画像 (Redis)                  │
                       │                       • 热点 FAQ 匹配 (Redis)             │
                       │                       • RAG 文档检索 (Redis Vector)       │
                       │                    3) 调用 LLM (DashScope)               │
                       │                       • 纯文本 → 文本 ChatClient          │
                       │                       • 带图片 → VL 多模态 ChatClient      │
                       │                    4) 流式接收 → StreamingSentenceSplitter│
                       │                       ┌─ 逐句下发 aiOutput ──► 显示文本   │
                       │                       │  └─ 逐句投递 TTS ────► synthesize │
                       │  ◄── 音频帧(0x01+PCM) │◄── 7B header + PCM ◄───────────  │
                       │  (AVSyncPlayer 播放)   │  └ 剥离 header 的裸 PCM 整句────► MuseTalk
                       │                       │                       audio_end 触发推理
                       │  ◄── 视频帧(0x03+H264)│◄────── H.264 AU 流 ◄───────────  │
                       │  (MediaCodec 解码渲染) │                                   │
                       │  ◄── responseDone ──  │  (LLM 流结束)                     │
```

> **音画同步（客户端 AVSyncPlayer）**：音视频在后端为**纯透传**（不排队、不同步），Jitter Buffer 与同步职责下放客户端。前端以音频播放位置为主时钟，按帧 PTS 对齐 H.264 视频帧（25fps / 40ms 一帧），中后期队列饿死或撑爆时按策略丢帧，保证口型与语音对齐。

Android 麦克风采集 → PCM 二进制帧 → WebSocket → Java 后端

### 4.4 打断流程

```
Android → {"type":"interrupt"}
    → MuseTalkConnector.interrupt()  → 停止视频生成 + 清队列
    → CosyVoiceConnector.interrupt() → 清 PCM 缓冲 + 停止合成 + 清队列

```

### 4.5 AI 路线推荐流程 ★ v2 新增

```
用户在对话页点"生成路线" → {"type":"routeGenerate"}
    → RouteRecommendationService.generateAndPush(ctx)
    → 读取用户偏好 + 景点知识库
    → expertChatClient 结构化输出有序地标 (title/summary/stops[])
    → 逐节点调用 AmapClient 解析坐标 (高德 POI, GCJ-02, Redis 缓存)
       └ 解析失败 → resolved=false, 坐标空 (降级)

    → routeTimeline 下发完整 RoutePlanVO

    → 置该节点 ARRIVED, 指针前移到下一节点 CURRENT
    → routeUpdate 下发更新后的数轴

关闭 → {"type":"routeClose"} → 清除 → routeClosed
```

### 4.6 知识文档 RAG 流程

```
管理员上传文件
    → OSS 存储 (spring-file-storage)
    → RabbitMQ (doc.convert.request)
    → markitdown-worker: 下载 → MarkItDown 解析 → Markdown
    → RabbitMQ (doc.convert.result)
    → DocumentVectorListener: MarkdownDocumentReader → TokenTextSplitter(800 字符块)

```

### 5.3 前端通信协议设计

#### 5.3.1 WebSocket 二进制帧协议

客户端与服务端之间通过**首字节（typeFlag）**区分二进制帧类型：

| 首字节 | 类型 | 帧结构 | 说明 |
| --- | --- | --- | --- |
| `0x01` | 音频 PCM | `[0x01][sentenceId 2B][ptsMs 4B][PCM N]`（7 字节 header） | CosyVoice 合成音频，16kHz s16le mono，客户端 AudioTrack 直接播放 |
| `0x03` | 视频帧 | `[0x03][sentenceId 2B][ptsMs 4B][keyFrame 1B][H.264 N]`（8 字节 header） | MuseTalk H.264 access unit，客户端 MediaCodec 解码渲染 |

> v1.0 中视频为 JPEG 帧（`0x02`），v2 已升级为 **H.264 流式编码**，配合客户端 `AVSyncPlayer`（MediaCodec H.264 解码 + PCM AudioTrack + PTS 音画同步）。

#### 5.3.2 WebSocket 连接规范（v2 变更）

```
ws://{host}:8080/ai-project/chat?token=<JWT>&attractionId=<id>
```

- 认证：URL 参数 `token` 或 Header `Authorization: Bearer <JWT>`，由 `WSJwtHandshakeInterceptor` 握手校验
- 连接参数：`attractionId`（必填）
- 空闲超时：30 分钟无活动自动断开（`WsIdleDetector`）

> v1.0 路径为 `/ws/chat/{userId}/{attractionId}`（路径参数），v2 改为 `/chat?token=&attractionId=`（查询参数 + JWT），userId 从 Token 解析。

### 6.4 ID 与会话标识策略

- **业务主键**：统一雪花 ID（MyBatis-Plus `assign_id`），全局唯一、趋势递增；Java 端 `Long`，**前端必须以 String 传递**，避免 JS Number 53 位精度丢失。
- **会话标识（v2）**：`conversationId = UUID.randomUUID()`，每次 WS 连接独立生成，支持同景点多次独立对话；作为聊天记忆 / 旅游历史 / 体验分析的关联键。

## 7. AI 服务设计

### 7.1 LLM 大模型架构

#### 7.1.1 多 ChatClient 策略

后端配置多个 `ChatClient` Bean，按场景分流（具体模型可在配置中切换）：

| ChatClient Bean | 用途 | 特点 |
| --- | --- | --- |
| `vlGuideChatClient` | 拍照提问 / 图片识别 | 视觉-语言多模态，文本+图片联合输入 |
| 文本导游 ChatClient | 常规文本对话 | 深度推理、长文本流式生成，挂 RAG + ChatMemory |
| `etlChatClient` | 文档向量化 / FAQ 生成 | 低温度，结构化、确定性输出 |
| `expertChatClient` | 路线推荐 / 情感分析 / 服务建议 | 低温度，结构化 JSON 输出 |

#### 7.1.2 提示词组装策略（DynamicPromptService）

```
System Prompt = 基础人设
              + 用户画像 (Redis Hash)
              + 导游偏好 (语言/风格/深度/兴趣)
              + 热点 FAQ 匹配 (Redis)
              + RAG 文档检索 Top-K (Redis Vector, 按 attractionId 过滤)
              + 对话历史 (JDBC ChatMemory, 窗口最近 10 轮)
```

### 7.2 RAG 向量检索引擎

```
文档 → MarkItDown 转换 → TokenTextSplitter (800 字符块, 表格保护)
    → Spring AI Embedding (DashScope text-embedding-v4)
    → Redis VectorStore (HNSW 索引, COSINE 相似度, prefix "attraction:")
    → 检索时同模型向量化用户问题 → Top-K 相似度搜索 (按 attractionId + type 过滤)
```

### 7.3 TTS 语音合成

| 参数 | 说明 |
| --- | --- |
| 模型 | CosyVoice3 |
| 合成方式 | 零样本（Instruct），仅需 1 条参考音频 + 对应文本 |
| 内部/输出采样率 | 24kHz → 重采样 16kHz |
| 输出格式 | s16le PCM 单声道，含 7 字节 header（typeFlag/sentenceId/ptsMs） |
| 音色管理 | 按 `attraction_id` 加载对应 `.wav`，全局共享 `prompt.txt` |
| 并发控制 | GPU 串行锁 + 单 worker 保证逐句顺序 |
| 预热 | 启动时触发首次推理，消除冷启动 |

### 7.4 数字人视频生成

| 参数 | 说明 |
| --- | --- |
| 模型 | MuseTalk (UNet + SD-VAE + Whisper-tiny) |
| 输入 | 16kHz PCM + 预加载头像视频 |
| 输出 | **H.264** 帧流 @ 25fps，每帧含 8 字节 header（`0x03`/sentenceId/ptsMs/keyFrame） |
| 推理加速 | 流水线重叠（双 CUDA Stream）、BATCH=48、TeaCache、torch.compile、FP16、TF32、H.264 线程池编码 |
| 头像缓存 | 每景点预处理一次（人脸检测 + VAE 编码）缓存于 GPU |
| 中断 | `cancel_flag` 立即停止当前推理 + 清缓存 |

### 7.5 路线推荐 AI（RouteRecommendationService）★ v2 新增

```
expertChatClient 结构化输出 → RoutePlanVO {title, summary, stops[]}
    → 每个 stop 调 AmapClient 解析坐标 (高德 POI 文本/周边检索, GCJ-02)
    → Redis 缓存 POI 结果 (按 attractionId/keyword)
    → 解析失败优雅降级 (resolved=false)
```

- 坐标系 **GCJ-02**，与前端高德定位统一，避免坐标漂移
- 节点状态机：`UPCOMING`(未到达) → `CURRENT`(进行中) → `ARRIVED`(已到达)

│                              │ WS  │                              │
│  • Java 后端 (8080)          │◄───►│  • MuseTalk (6006)           │
│  • MySQL Docker              │     │  • SoVITS/CosyVoice (6008)   │
│  • Redis Stack Docker        │     │                              │
│  • RabbitMQ Docker           │◄───►│  MuseTalk 经公网 AMQP 连接     │
│  • markitdown-worker Docker  │AMQP │  CPU 服务器 RabbitMQ 收管理指令 │
└──────────────────────────────┘     └──────────────────────────────┘
```

**关键设计决策：**
- AI 推理与业务逻辑分离：GPU 密集计算在 AutoDL，CPU 密集业务在云服务器
- 跨主机 WebSocket 串联：Java 后端作为"中继"，连接客户端与 Python AI 服务，音视频纯透传
- AutoDL 自定义服务：暴露 6006/6008 获得公网代理地址
- RabbitMQ 跨主机访问：MuseTalk 通过公网连接 CPU 服务器 RabbitMQ 接收管理指令

### 8.2 启动顺序

```
1. CPU 云服务器：docker compose up -d (MySQL + Redis + RabbitMQ + markitdown-worker)
2. AutoDL 控制台：配置自定义服务端口 6006/6008
3. AutoDL GPU 实例：启动 SoVITS (6008) → 启动 MuseTalk (6006)
4. CPU 云服务器：java -jar ai-start.jar --spring.profiles.active=prod
```

## 10. 安全设计

### 10.1 认证与鉴权

```
登录 → JWT Token (HS384) → Redis 存储 (7 天 TTL, 剩余 <24h 续期)
    → 拦截器校验 (Authorization Header / WS query token + Redis TTL)
    → ThreadLocal 上下文 (UserContext / AdminContext)
    → 请求结束自动清理
```

- 登录/注册接口白名单，不经拦截器
- 用户和管理员使用独立拦截器和上下文
- WebSocket 由 `WSJwtHandshakeInterceptor` 在握手阶段校验 token，userId 从 Token 解析

### 10.2 限流策略

- **令牌桶算法**：`ai:chat:{userId}` 维度，每分钟约 10 次 AI 调用
- **实现**：`RateLimiterUtil` + Redis 原子操作

### 10.3 数据安全

| 措施 | 说明 |
| --- | --- |
| 密码加密 | BCrypt 哈希存储；密码字段 `select=false` 不参与查询 |
| JWT 签名 | HS384 算法，密钥 ≥ 256 位 |
| 中间件密码 | 应通过环境变量/外部 Vault 注入 |
| OSS 访问 | RAM AccessKey，最小权限原则 |
| 数据库端口 | MySQL/Redis 仅内部访问，不暴露公网 |

> **安全提醒**：`application-dev.yml` / `application-prod.yml` 当前含硬编码凭据（阿里云 Key、DB/Redis/RabbitMQ 密码），切勿提交到公开仓库，建议迁移到环境变量或密钥管理服务。

### 10.4 输入校验

- Controller 层 `@Valid` + JSR-303 注解校验
- 全局异常处理器统一返回校验错误
- 文件上传限制格式与大小（图片 `image/*`、文档 `.doc/.docx/.pdf`、视频 `video/*`）

## 11. 性能与可靠性设计

### 11.1 性能优化措施

| 层面 | 优化手段 |
| --- | --- |
| **LLM 调用** | 流式输出 + StreamingSentenceSplitter 逐句推送，降低首字延迟感知 |
| **TTS 合成** | 单线程串行执行器保证语音顺序；逐句投递不阻塞 LLM 流 |
| **数字人生成** | 双 CUDA Stream 流水线重叠、BATCH=48、TeaCache、torch.compile、FP16、H.264 线程池编码 |
| **音视频传输** | 后端纯透传不排队，Jitter Buffer/同步下放客户端 AVSyncPlayer（音频主时钟门控 lip-sync） |
| **路线 POI** | AmapClient 解析结果 Redis 缓存，按 attractionId/keyword 命中复用 |
| **数据库** | MyBatis-Plus 游标分页、连接池复用、索引优化、逻辑删除 |
| **缓存** | 用户画像 (24h)、FAQ 热点、JWT、激活路线 |
| **消息队列** | 异步处理文档向量化、旅游历史落库、视频管理等非实时操作 |

### 11.2 会话管理

| 组件 | 职责 |
| --- | --- |
| `ChatSessionRegistry` | 全局会话注册表（ConcurrentHashMap），管理所有在线 WS 连接 |
| `ChatSessionContext` | 单会话上下文：用户 WS、MuseTalk WS、CosyVoice WS、TTS 线程池、conversationId(UUID) |
| `OutboundPacer` | 出站视频帧按 PTS 时钟节拍下发，防止突发灌包撑爆下游缓冲（bufferbloat） |
| `WsIdleDetector` | 定时检测空闲会话，超时主动断开释放资源 |

### 11.3 异常处理

| 层级 | 机制 |
| --- | --- |
| Controller | 全局异常处理器 `@RestControllerAdvice`，统一返回 `Result` 错误结构 |
| WebSocket | `handleTransportError` 捕获传输异常，清理会话资源 + 通知客户端 |
| AI 服务连接 | MuseTalk/CosyVoice 连接失败记录日志，不影响主会话建立 |
| 路线降级 | 高德解析失败时节点 `resolved=false`，路线仍下发 |
| 消息队列 | 消费者手动 ACK + 重试 + 死信队列（Quorum 队列高可用） |

### 11.4 可观测性

| 维度 | 方式 |
| --- | --- |
| 应用日志 | SLF4J + Logback，关键路径埋点（会话建立、AI 调用、异常） |
| AI 服务日志 | Python logging，统一时间戳格式 |
| 容器日志 | `docker logs` 查看中间件状态 |
| 健康检查 | SoVITS `/health`，MuseTalk 启动日志验证，Redis 预加载状态键 |
