# 知途灵眸 — 产品方案介绍PPT大纲

> 中软杯参赛项目「沧海数智」团队 | 用于AI生成PPT工具输入素材

---

## 一、需求场景分析

- **痛点**：传统景区导览依赖纸质地图/语音讲解器，缺乏个性化、互动性差，游客难以获得"随身导游"式体验
- **目标场景**：景区、博物馆、主题乐园等需要智能导览的场所
- **用户画像**：
  - C端游客：浏览景点、AI对话、个性化路线、历史记录
  - B端景区管理员：内容管理、数据运营
- **核心诉求**：沉浸式讲解 + 智能路线规划 + 知识准确性（不能瞎编景点信息）

---

## 二、整体方案设计

- **产品定位**：以AI数字人为核心交互载体的智能导览系统
- **三层架构**：
  - Android客户端（游客端 + 管理员端）
  - Java后端服务层（CPU云服务器）
  - AI推理服务层（AutoDL GPU）
- **核心链路**：一条WebSocket承载对话/语音/视频/路线/表情五类业务
- **算力分离设计**：AI推理独立部署GPU实例，支持多景区横向扩展

---

## 三、核心技术与模型

- **数字人生成**：MuseTalk（UNet + VAE + Whisper-tiny），音频驱动口型同步，H.264实时视频流
- **语音合成**：CosyVoice3零样本TTS，16kHz PCM流式输出
- **语音识别**：阿里云NLS实时转写 + 实时字幕
- **对话大模型（多Client分工）**：
  - llmGuideChatClient（qwen3.6-flash）—— 导游对话
  - expertChatClient（qwen3.7-max）—— 路线规划
  - emotionVisionChatClient（qwen3.7-plus）—— 表情分析
- **RAG知识库**：文档 → Markdown → 向量化（HNSW + text-embedding-v4）→ Redis VectorStore检索
- **音画同步**：客户端AVSyncPlayer以音频为主时钟对齐H.264帧，后端OutboundPacer按PTS节拍下发，防止bufferbloat

---

## 四、创新要点

- **多模态融合交互**：文本 + 语音 + 前置摄像头表情分析，同一WebSocket承载全部业务类型
- **"灵动岛"路线数轴**：AI结构化生成个性化路线 + 高德GPS自动到达判定 + 手动兜底
- **音画同步工程方案**：双端协同（后端纯透传 + 客户端主时钟对齐），解决行业常见的口型不同步问题
- **情感/表情双维度分析驾驶舱**：LLM文本情感分析 + vision模型表情分类，管理端可视化呈现
- **打断机制**：支持游客随时打断数字人讲解，全链路资源清理重建（PTS复位、队列清空）
