## 1. 产品概述

### 1.1 产品定位

AI 数字人导游是一款面向景区、博物馆、主题乐园等场景的**智能导览系统**。系统以 **AI 数字人** 为核心交互载体，通过 Android 客户端为用户提供自然语言对话式的导游讲解服务，让游客获得"随身 AI 导游"的沉浸式体验。

### 1.2 核心价值

| 维度 | 说明 |
| --- | --- |
| **沉浸式交互** | AI 数字人口型同步、实时语音合成，提供"面对面"讲解体验 |
| **多模态输入** | 支持文本、语音（实时转写）、拍照等多种交互方式 |
| **知识驱动** | 基于 RAG 技术，将景区资料文档转化为可检索的知识库，确保回答准确有据 |
| **智能化管理** | 管理员端提供游客情感分析、热门问题排行、AI 服务建议等数据驾驶舱 |
| **可扩展架构** | 算力分离部署，AI 推理服务独立伸缩，支持多景区横向扩展 |

### 1.3 用户角色

| 角色 | 职责 |
| --- | --- |
| **游客（C 端用户）** | 浏览景点列表，与 AI 数字人导游对话，查看旅游历史 |
| **景区管理员（B 端用户）** | 管理景点信息、上传知识文档、配置数字人形象、查看数据统计分析 |

### 1.4 终端形态

- **前端**：Android 原生应用（微信式聊天界面 + 数字人视频渲染）
- **后端 API**：Spring Boot RESTful + WebSocket 服务
- **管理后台**：集成于 Android 管理端

### 3.2 游客端功能详述

#### 3.2.1 用户认证

- **注册**：账号 4-16 位字母/数字/下划线，密码 6-20 位，昵称 1-20 字符
- **登录**：返回 JWT Token（HS384 签名）+ 用户雪花 ID
- **鉴权**：所有非登录/注册接口通过 `UserJwtInterceptor` 拦截，Token 存 Redis（7 天过期）
- **上下文**：`UserContext`（ThreadLocal）在请求生命周期内持有用户 ID

#### 3.2.2 AI 导游对话

核心交互入口，通过 WebSocket 长连接实现**实时双向通信**：

```
客户端 ──WebSocket──► Java 后端 ──WebSocket──► SoVITS (TTS)
                       │    ▲
                       │    ├── Redis (向量检索 + 用户画像)
                       │    ├── DashScope (LLM 大模型)
                       │    └── MySQL (聊天记忆)
                       ▼
                    MuseTalk (数字人视频)
```

**消息类型矩阵：**

| type | 方向 | 载体 | 说明 |
| --- | --- | --- | --- |
| `text` | 客户端→后端 | Text (JSON) | 文本输入 |
| `micOn`/`micOff` | 客户端→后端 | Text (JSON) | 麦克风开关 |
| `photo` | 客户端→后端 | Text (JSON, Base64) | 拍照上传 |
| `camera` | 客户端→后端 | Text (JSON) | 摄像头开关 |
| `interrupt` | 客户端→后端 | Text (JSON) | 主动打断数字人 |
| `ping`/`pong` | 双向 | Text (JSON) | 心跳检测 |
| `aiOutput` | 后端→客户端 | Text (JSON) | AI 文本回复（逐句推送） |
| `responseDone` | 后端→客户端 | Text (JSON) | 回复完成通知 |
| `ready` | 后端→客户端 | Text (JSON) | 数字人准备就绪 |
| `done` | 后端→客户端 | Text (JSON) | 单句生成完毕 |
| `allDone` | 后端→客户端 | Text (JSON) | 会话初始化完成 |
| `error` | 后端→客户端 | Text (JSON) | 错误通知 |
| `0x01` 头帧 | 后端→客户端 | Binary | TTS 音频 PCM 流 (16kHz s16le mono) |
| `0x02` 头帧 | 后端→客户端 | Binary | 数字人视频 JPEG 帧流 |
| 裸 PCM | 客户端→后端 | Binary | 麦克风采集音频（送 NLS 转写） |

#### 3.2.3 景点浏览

- 游标分页（基于雪花 ID），支持关键词搜索
- 返回景点 ID、名称、封面图
- 用户点击景点进入 WebSocket 对话（路径参数：`userId` + `attractionId`）

#### 3.2.4 旅游历史

- 游标分页展示历史对话记录
- 支持关键词搜索和类型筛选
- 支持单条删除、评分评价（1-5 分 + 文字反馈）
- 每次 WS 连接建立时自动生成一条旅游历史记录（通过 RabbitMQ 异步落库）

### 3.3 管理员端功能详述

#### 3.3.1 景点管理

- 景点名称、封面图、类型（7 种分类：主题乐园/博物馆与展馆/自然公园/风景名胜与休闲度假/历史文化/古镇水乡/动植物园与水族馆/现代地标）
- 支持新增、编辑、删除、批量删除
- 游标分页 + 关键词搜索 + 类型筛选

#### 3.3.2 知识文档管理

```
管理员上传文件 → OSS 存储 → RabbitMQ (doc.convert.request)
    → markitdown-worker 下载+解析 → Markdown 文本
    → RabbitMQ (doc.convert.result) → Java 后端
    → TokenTextSplitter (800 字符块) → Redis VectorStore
    → MySQL 元数据记录
```

- 支持格式：`.doc`、`.docx`、`.pdf`
- 上传后返回 `taskId`，前端每 2 秒轮询解析状态（PROCESSING / SUCCESS / FAILED）
- 解析完成的文档自动向量化存入 Redis，用于 RAG 检索

#### 3.3.3 数字人管理

- 配置景点对应的数字人肖像图（OSS 地址）
- 上传驱动视频（`.mp4`），后端通过 RabbitMQ 通知 MuseTalk 预加载
- 支持新增、编辑、删除

#### 3.3.4 数据分析驾驶舱

| 分析维度 | 图表类型 | 数据来源 | 时间窗口 |
| --- | --- | --- | --- |
| 热门问题排行 | 柱状图 (Top N) | Redis 热点 FAQ 统计 → MySQL | 7/30 天 |
| 聊天服务使用趋势 | 折线图 | MySQL 聊天记录聚合 | 1/7/30 天 |
| 用户满意度趋势 | 折线图 | MySQL 评价记录 | 7/30 天 |
| 游客情感分析 | 折线图 + 环形图 | LLM 情感分析结果 | 7/30 天 |
| 情感与关注点卡片 | 指标卡片 | LLM 综合分析 | 1/7/30 天 |
| AI 服务优化建议 | 富文本 | LLM 自动生成 | 7/30 天 |

## 4. 核心技术流程

### 4.1 AI 导游对话全链路

```
                    Android                      Java 后端                      AI 服务
                       │                            │                             │
  ── 建立连接 ──►  WS /ws/chat/{userId}/{attractionId}                          │
                       │                            │                             │
                       │                    1) JWT 鉴权 (路径参数)                │
                       │                    2) 注册 ChatSessionContext            │
                       │                    3) 缓存用户信息 + 会话ID → Redis      │
                       │                    4) 发送旅游历史记录 → RabbitMQ        │
                       │                    5) 连接 MuseTalk WS ──────────►  init + 预加载头像
                       │                    6) 连接 CosyVoice WS ──────────►  init + 加载音色
                       │                            │                             │
                       │  ◄── allDone ────          │                             │
                       │                            │                             │
  ── 文本输入 ──►  {"type":"text","text":"..."}     │                             │
                       │                            │                             │
                       │                    1) 令牌桶限流检查                     │
                       │                    2) DynamicPromptService 拼装提示词     │
                       │                       • 用户画像 (Redis)                  │
                       │                       • 热点FAQ 匹配 (Redis)              │
                       │                       • RAG 文档检索 (Redis Vector)       │
                       │                    3) 调用 LLM (DashScope)               │
                       │                       • 纯文本 → llmGuideChatClient       │
                       │                       • 带图片 → vlGuideChatClient        │
                       │                    4) 流式接收 → StreamingSentenceSplitter│
                       │                       ┌─ 逐句下发 aiOutput ──► 显示文本   │
                       │                       │  ┌─ 逐句投递 TTS ──────► synthesize│
                       │                       │  │                   (CosyVoice3 │
                       │                       │  │                    零样本合成) │
                       │                       │  │                              │
                       │  ◄── 0x01 PCM ────────│◄─┼── PCM 流 ◄────────────────   │
                       │  (音频实时播放)        │  │                              │
                       │                       │  └── chunk_end → 整句PCM ────►  MuseTalk
                       │                       │                         audio_end 生成视频帧
                       │                       │                                    │
                       │  ◄── 0x02 JPEG ───────│◄────── JPEG 帧流 ◄───────────    │
                       │  (数字人视频渲染)      │                                    │
                       │                       │                                    │
                       │  ◄── responseDone ──  │  (LLM 流结束)                     │
```

### 4.2 语音对话流程

```
Android 麦克风采集 → PCM 二进制帧 → WebSocket → Java 后端
    → NlsTranscriberManager (阿里云 NLS 实时语音识别)
    → 转写文本 → AiChatService.invoke()
    → (后续同文本对话流程)
```

### 4.3 拍照提问流程

```
Android 拍照 → Base64 编码 → {"type":"photo","photo":"..."}
    → ChatSessionContext.setPendingImage()
    → 下一条 {"type":"text","text":"..."}
    → AiChatService 检测到 pendingImage → 调用 VL 多模态模型
    → 流式返回（同文本流程）
```

### 4.4 打断流程

```
Android → {"type":"interrupt"}
    → MuseTalkConnector.interrupt() → 发 interrupt 到 MuseTalk（停止视频生成+清队列）
    → CosyVoiceConnector.interrupt() → 清 PCM 缓冲 + 发 interrupt 到 CosyVoice（停止合成+清队列）
    → shutdownNow TTS 单线程池 → 新建线程池 → 可继续对话
```

### 4.5 知识文档 RAG 流程

```
管理员上传文件
    → OSS 存储 (spring-file-storage)
    → RabbitMQ (doc.convert.request)
    → markitdown-worker: 下载 → MarkItDown 解析 → Markdown 文本
    → RabbitMQ (doc.convert.result)
    → DocumentVectorListener: MarkdownDocumentReader → TokenTextSplitter(800 字符块)
    → Redis VectorStore (index: attraction_index, prefix: "attraction:")
    → MySQL 元数据记录

AI 对话时:
    用户问题 → VectorSearchService.similaritySearch()
    → 检索 Top-K 相关文档块
    → DynamicPromptService 拼入 System Prompt
    → LLM 基于文档内容回答
```

### 4.6 FAQ 热点演化流程

```
用户对话中 LLM 未能回答的问题
    → 积累到 Redis Set (faq:miss:{attractionId})
    → FaqEvolutionTask (定时任务) 批量处理
    → LLM 对积累的问题进行聚类+标准化
    → 生成标准 FAQ 问法 → 存入 MySQL + Redis 缓存
    → 后续对话匹配到相同问题时直接返回标准答案
```

│   ├── biz-attractions # 景点模块：景点 CRUD、文件上传、数字人管理
│   └── biz-ai        # AI 核心模块：WebSocket 聊天、RAG、TTS/MuseTalk 连接器
│
└── ai-start          # 启动入口
    ├── @SpringBootApplication
    ├── @EnableScheduling
    └── application.yml / application-{dev,prod}.yml
```

#### 5.1.3 模块内分层规范

```
controller  →  service (接口)  →  service/impl (实现)  →  mapper (MyBatis-Plus)
     ↕
converter (MapStruct: Entity ↔ DTO ↔ VO)
```

- Service 层继承 `ServiceImpl<Mapper, Entity>`，自动获得 CRUD 能力
- Controller 层统一返回 `Result<T>`（code: 1=成功, 400=客户端错误, 500=服务端错误）
- `@Valid` 触发 DTO 校验，`MethodArgumentNotValidException` 由全局异常处理器捕获

### 5.2 AI 服务端架构

#### 5.2.1 TTS 服务（SoVITS / CosyVoice）

```
FastAPI (lifespan 预加载模型)
├── /ws/tts — WebSocket 合成端点
│   ├── 协议: init → synthesize (带 attraction_id + session_id) → PCM chunk + chunk_end
│   ├── CosyVoice3 零样本: {attraction_id}.wav + prompt.txt → 24kHz 语音
│   └── 后处理: 24kHz → 16kHz 重采样 + s16le PCM 输出
├── /health — 健康检查
├── /voices — 音色列表
└── /voices/reload — 热加载音色文件
```

#### 5.2.2 数字人服务（MuseTalk）

```
FastAPI (lifespan 预加载模型 + 扫描视频目录预加载)
├── /ws/infer — WebSocket 推理端点
│   ├── 协议: init (attraction_id) → 接收 PCM + audio_end → 输出 JPEG 帧
│   ├── 推理管线:
│   │   audio → Whisper-tiny (音频特征提取) → UNet (潜在空间推理)
│   │   → VAE Decoder (潜在空间→图像) → GPU Blend (口型混合)
│   │   → NVJPEG 编码 → JPEG 二进制帧
│   ├── 性能优化: torch.compile、TeaCache、双 CUDA Stream 流水线
│   └── 中断支持: cancel_flag → 停止推理 + 清空缓存
├── RabbitMQ Consumer (video.preload.queue / video.delete.queue)
│   └── 接收后端指令动态加载/卸载头像视频
└── 启动预加载: 扫描 BASE_VIDEO_DIR/*.mp4 → load_avatar → warmup
```

## 7. AI 服务设计

### 7.1 LLM 大模型架构

#### 7.1.1 模型策略

| ChatClient Bean | 模型 | 用途 | 特点 |
| --- | --- | --- | --- |
| `vlGuideChatClient` | 通义千问 VL 多模态 | 拍照提问 / 图片识别场景 | 支持文本+图片联合输入 |
| `llmGuideChatClient` | 通义千问 (qwen3.6-plus) | 常规文本导游对话 | 深度推理，长文本生成 |
| (ETL Client) | 通义千问 (qwen3.6-flash) | 文档向量化 / FAQ 生成 | 轻量快速，批量处理 |
| (Analysis Client) | 通义千问 (qwen3.6-plus) | 情感分析 / 服务建议 | 结构化 JSON 输出 |

#### 7.1.2 提示词组装策略（DynamicPromptService）

```
System Prompt = 基础人设
              + 用户画像 (Redis Hash 读取)
              + 热点 FAQ 匹配 (Redis ZSet 查询)
              + RAG 文档检索结果 (Redis Vector 相似度搜索 Top-K)
              + 对话历史 (JDBC ChatMemory, 最近 10 轮)
```

### 7.2 RAG 向量检索引擎

```
文档 → MarkItDown 转换 → TokenTextSplitter (800 字符块, 表格保护)
    → Spring AI Embedding (DashScope text-embedding-v3)
    → Redis VectorStore (FLAT 索引, COSINE 相似度)
    → 检索时同模型向量化用户问题 → Top-K 相似度搜索
```

### 7.3 TTS 语音合成

| 参数 | 说明 |
| --- | --- |
| 模型 | CosyVoice3 (Fun-CosyVoice3-0.5B) |
| 合成方式 | 零样本（Instruct 模式），仅需 1 条参考音频 + 对应文本 |
| 内部采样率 | 24kHz |
| 输出采样率 | 16kHz（重采样后输出） |
| 输出格式 | s16le PCM 单声道 |
| 语速 | 0.9（可配置 `TTS_SPEED`） |
| 音色管理 | 按 `attraction_id` 加载对应 `.wav` 文件，全局共享 `prompt.txt` |
| 预热 | 启动时用 `WARMUP_TEXT` 触发首次推理，消除冷启动 |

### 7.4 数字人视频生成

| 参数 | 说明 |
| --- | --- |
| 模型 | MuseTalk (UNet + SD-VAE + Whisper-tiny) |
| 输入 | 16kHz PCM 音频 + 预加载头像视频 |
| 输出 | 480×854 JPEG 帧流 @ 25fps |
| 推理加速 | torch.compile (UNet + VAE)、TeaCache (相似帧跳过 UNet)、双 CUDA Stream 流水线、FP16 推理、TF32 matmul |
| 预热 | 启动时扫描视频目录 → load_avatar（帧预处理+GPU 上传）→ warmup（端到端推理） |
| 中断 | `cancel_flag` 立即停止当前推理，清空 TeaCache |

### 7.5 AI 服务 WebSocket 协议

#### SoVITS/CosyVoice (`/ws/tts`)

```
客户端 → 服务端 (Text/JSON):
  {"type":"init", "attraction_id":"...", "session_id":"..."}
  {"type":"synthesize", "text":"...", "attraction_id":"...", "session_id":"..."}
  {"type":"interrupt", "attraction_id":"...", "session_id":"..."}

服务端 → 客户端:
  Binary: PCM 音频块 (16kHz s16le mono)
  Text:   {"type":"chunk_end"}
  Text:   {"type":"ping"} / {"type":"error","message":"..."}
```

#### MuseTalk (`/ws/infer`)

```
客户端 → 服务端:
  Text:   {"type":"init", "attraction_id":"..."}
  Binary: PCM 音频数据
  Text:   {"type":"audio_end"}
  Text:   {"type":"interrupt", "attraction_id":"...", "session_id":"..."}

服务端 → 客户端:
  Binary: JPEG 视频帧
  Text:   {"type":"ready"}  /  {"type":"done"}  /  {"type":"error","message":"..."}
  Text:   {"type":"ping"} → 客户端应回应 {"type":"pong"}
```

### 8.1 算力分离策略

```
┌──────────────────────────────┐     ┌──────────────────────────────┐
│      CPU 云服务器              │     │     AutoDL GPU 实例           │
│  (阿里云 ECS / 腾讯云 CVM)     │     │  (RTX 5090 32GB)              │

**关键设计决策：**
- AI 推理与业务逻辑分离：GPU 密集计算在 AutoDL 实例，CPU 密集型业务在云服务器
- 跨主机 WebSocket 串联：Java 后端作为"中继"，连接客户端与 Python AI 服务
- AutoDL 自定义服务：暴露 6006/6008 端口获得公网代理地址

1. CPU 云服务器：docker compose up -d (MySQL + Redis + RabbitMQ + markitdown-worker)
2. AutoDL 控制台：配置自定义服务端口 6006/6008
3. AutoDL GPU 实例：启动 SoVITS (Port 6008) → 启动 MuseTalk (Port 6006)
4. CPU 云服务器：java -jar ai-start.jar --spring.profiles.active=prod

## 10. 安全设计

### 10.1 认证与鉴权

```
登录 → JWT Token (HS384) → Redis 存储 (7天TTL)
    → 拦截器校验 (Authorization Header + Redis TTL)
    → ThreadLocal 上下文 (UserContext / AdminContext)
    → 请求结束自动清理
```

- 登录/注册接口白名单，不经过拦截器
- 用户和管理员使用独立的拦截器和上下文
- WebSocket 连接通过路径参数中的 `userId` + JWT 鉴权

### 10.2 限流策略

- **令牌桶算法**：`ai:chat:{userId}` 维度，每分钟 10 次 AI 调用
- **实现**：`RateLimiterUtil` + Redis 原子操作

### 10.3 数据安全

| 措施 | 说明 |
| --- | --- |
| 密码加密 | BCrypt 哈希存储 |
| JWT 签名 | HS384 算法，密钥 ≥ 256 位 |
| 中间件密码 | 环境变量注入，不写入配置文件 |
| OSS 访问 | RAM AccessKey，最小权限原则 |
| 数据库端口 | MySQL(3306)/Redis(6379) 仅内部访问，不暴露公网 |

### 10.4 输入校验

- Controller 层 `@Valid` + JSR-303 注解校验
- 全局异常处理器统一返回校验错误
- 文件上传限制格式和大小（图片 `image/*`，文档 `.doc/.docx/.pdf`，视频 `video/*`）

## 11. 性能与可靠性设计

### 11.1 性能优化措施

| 层面 | 优化手段 |
| --- | --- |
| **LLM 调用** | 流式输出 + StreamingSentenceSplitter 逐句推送，降低首字延迟感知 |
| **TTS 合成** | 单线程串行执行器，保证语音顺序；逐句投递不阻塞 LLM 流 |
| **数字人生成** | torch.compile、TeaCache（高相似帧跳过 UNet）、双 CUDA Stream 流水线、FP16 推理 |
| **数据库** | MyBatis-Plus 游标分页、连接池复用、索引优化 |
| **缓存** | Redis 用户画像缓存 (24h)、FAQ 热点缓存、JWT Token 缓存 |
| **消息队列** | 异步处理文档向量化、旅游历史落库等非实时操作 |

### 11.2 会话管理

| 组件 | 职责 |
| --- | --- |
| `ChatSessionRegistry` | 全局会话注册表（ConcurrentHashMap），管理所有在线 WS 连接 |
| `ChatSessionContext` | 单会话上下文：封装用户 WS 会话、MuseTalk WS 会话、CosyVoice WS 会话、TTS 线程池 |
| `WsIdleDetector` | 定时检测空闲会话，超时主动断开释放资源 |

### 11.3 异常处理

| 层级 | 机制 |
| --- | --- |
| Controller | 全局异常处理器 `@RestControllerAdvice`，统一返回 `Result` 错误结构 |
| WebSocket | `handleTransportError` 捕获传输异常，清理会话资源 + 通知客户端 |
| AI 服务连接 | MuseTalk/CosyVoice 连接失败时记录日志，不影响主会话建立 |
| 消息队列 | 消费者手动 ACK + 重试机制 + 死信队列 |

### 11.4 可观测性

| 维度 | 方式 |
| --- | --- |
| 应用日志 | SLF4J + Logback，关键路径埋点（会话建立、AI 调用、异常） |
| AI 服务日志 | Python logging，统一时间戳格式 |
| 容器日志 | `docker logs` 查看中间件运行状态 |
| 健康检查 | SoVITS `/health` 端点，MuseTalk 启动日志验证 |
