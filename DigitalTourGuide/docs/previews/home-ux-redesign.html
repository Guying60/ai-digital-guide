用户端改动要点

  • 拆区：上半「导航区」可点进聊天记录；下半「操作区」只放结束/继续/评价
  • 显性文案：加「查看对话记录 ›」，不要靠用户猜
  • 末条预览：展示最近一句对话，一眼知道卡片=聊天历史
  • 弱化按钮抢戏：「结束」缩短文案；继续对话仍是主按钮，但不盖住导航暗示
  • 可选：导航区右侧加聊天气泡图标，进一步强化心智

交互映射（保持现有业务）

  • 点导航区 → ChatHistoryActivity
  • 继续对话 → ChatActivity
  • 结束对话 → 本地标记 ended → 显示评价
  • 评价 → 评价弹窗
  • 长按删除逻辑可保留，或移到记录详情页更多菜单

更符合后台心智：点卡片就编辑；数据降为次级按钮

管理员端：为什么会误点

  • 后台产品里「点列表项 = 编辑」是强习惯
  • 当前整卡可点，但目标是数据分析，和习惯冲突
  • 「编辑」按钮虽在，却和卡片点击同级，没有主次叙事

怎么选 A / B

  • 方案 A：少改代码路径，只强化「卡片=数据」的文案与图标
  • 方案 B：改点击语义（卡片→编辑，按钮→数据），更贴合你「想编辑却点了卡片」的真实行为
  • 若管理员日常以改景点为主、看数据为辅 → 更推荐 B
  • 若产品强调运营看板优先 → 选 A，但必须有「查看运营数据 ›」
