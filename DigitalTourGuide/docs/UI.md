## 六、管理员端

### 6.1 景点管理

**功能目的**：管理员登录后的默认首页，管理全部景点的增删改查与数据分析入口。

#### 需展示的数据（每条景点）

| 字段             | 说明            |
| ---------------- | --------------- |
| `id`             | 景点 ID         |
| `attractionName` | 景点名称        |
| `coverUrl`       | 封面图          |
| `type`           | 景点类型（0~7） |

#### 需支持的操作

| 操作       | 行为                                          |
| ---------- | --------------------------------------------- |
| 关键词搜索 | 按景点名搜索                                  |
| 类型筛选   | 8 类 + 全部                                   |
| 分页加载   | 每页 6 条                                     |
| 点击景点   | 进入该景点的「数据分析」                      |
| 新增景点   | 进入「编辑景点」（无 ID，新建模式）           |
| 编辑景点   | 进入「编辑景点」（带 `attraction_id`）        |
| 删除景点   | 二次确认后删除单条                            |
| 批量删除   | 进入多选模式 → 勾选多条 → 二次确认 → 批量删除 |

**接口**：

- 列表：`GET admins/attractions?keyWord&type&lastId&pageSize=6`
- 删除：`DELETE admins/attractions/{attractionId}`
- 批量删除：`DELETE admins/attractions/batch`，Body: `{ ids: [] }`

**批量模式要求**：

- 可切换进入/退出多选
- 至少选 1 条才能执行删除
- 每条可单独勾选

**需设计的状态**：加载中、空列表、普通模式、批量多选模式、删除确认

### 6.2 编辑景点

**功能目的**：新建或编辑景点基础信息、上传封面、管理知识库文档，并跳转数字人配置。

#### 两种模式

| 模式 | 入参               | 行为                            |
| ---- | ------------------ | ------------------------------- |
| 新建 | 无 `attraction_id` | 先创建景点拿 ID，再允许上传文档 |
| 编辑 | 有 `attraction_id` | 回显已有数据，支持修改          |

#### 需编辑的字段

| 字段             | 说明                                |
| ---------------- | ----------------------------------- |
| `coverUrl`       | 景点封面，必填；仅支持 JPG/PNG      |
| `attractionName` | 景点名称，必填                      |
| `type`           | 景点类型，0~7                       |
| 知识库文档       | 最多 **4 个**文件槽位，支持 doc/pdf |

#### 需支持的操作

| 操作           | 说明                                      |
| -------------- | ----------------------------------------- |
| 上传/更换封面  | 选图 → 上传 OSS → 获得 URL                |
| 上传知识库文档 | 需先有景点 ID；上传后后台解析，需轮询状态 |
| 删除知识库文档 | 二次确认                                  |
| 保存           | 有字段变更时才可提交；新建/更新景点信息   |
| 进入数字人配置 | 跳转数字人管理（需先有景点 ID）           |

**接口**：

- 回显：`GET admins/attractions/{attractionId}`
- 文档列表：`GET admins/attractions/documents/{attractionId}`
- 新建：`POST admins/attractions`
- 更新：`PUT admins/attractions`
- 封面上传：`POST admins/file/cover`
- 文档上传：`POST admins/file/doc`
- 文档解析轮询：`GET admins/attractions/documents/{taskId}`（状态：PROCESSING / SUCCESS / FAILED，2 秒间隔）
- 删除文档：`DELETE admins/attractions/documents/{fileId}`

**校验规则**：

- 保存时：封面、景点名称必填
- 新建模式下无景点 ID 时不可上传文档
- 封面仅接受 jpeg/png
- 接口返回 400 时需提示并限制操作

**文档槽位状态**：

- 空槽（可上传）
- 上传中
- 解析中（轮询）
- 已就绪（显示文件名，可删除）
- 解析失败

**需设计的状态**：新建/编辑模式、未保存变更提示、保存中、上传中、解析轮询中、保存成功返回列表

### 6.3 数字人管理

**功能目的**：为指定景点配置 AI 数字人的参考视频形象，支持预加载与测试视频生成。

#### 入参

- `attraction_id`（必填，缺失则关闭页面）

#### 需展示的数据

| 字段         | 说明                   |
| ------------ | ---------------------- |
| 数字人 ID    | 配置后获得             |
| OSS 视频 URL | 源视频地址             |
| 预加载状态   | 上传后需等待预加载完成 |
| 测试视频 URL | 生成测试视频后获得     |

#### 需支持的操作

| 操作          | 说明                                                         |
| ------------- | ------------------------------------------------------------ |
| 查询现有配置  | 进入页面自动加载                                             |
| 上传/更换视频 | 选择本地视频 → 上传 → 自动保存数字人配置 → 触发预加载        |
| 预览视频      | 点击封面播放当前配置的视频                                   |
| 生成测试视频  | 需已配置数字人；输入自定义台词 → 提交 → 轮询状态 → 播放/下载 |
| 保存          | 上传成功后自动 upsert，无需单独保存                          |

**接口**：

- 查询：`GET admins/attractions/digital-human/{attractionId}`
- 新增/更新：`POST admins/attractions/digital-human`
- 视频上传：`POST admins/file/video?attractionId`
- 预加载轮询：`GET .../preload-status/{attractionId}`（SUCCESS / FAILED，2 秒间隔）
- 生成测试视频：`POST .../test-video/{attractionId}`，Body: `{ text }`
- 测试视频状态：`GET .../test-video-status/{attractionId}`（SUCCESS 含 videoUrl，3 秒间隔）

**校验**：

- 未选视频不能上传
- 未配置数字人不能生成测试视频

**需设计的状态**：

- 未配置 / 已配置
- 视频上传中
- 预加载中（轮询）
- 预加载成功 / 失败
- 测试视频生成中（轮询）
- 测试视频就绪 / 失败
- 视频预览播放

### 6.4 数据分析（容器页）

**功能目的**：针对单个景点，切换查看「数据概览」与「游客分析」两个子模块。

| 功能点   | 说明                      |
| -------- | ------------------------- |
| 入参     | `attraction_id`（必填）   |
| 模块切换 | 「数据概览」/「游客分析」 |
| 返回     | 回到景点管理列表          |

**需设计的状态**：两个子模块的选中态

---

### 6.5 数据概览

**功能目的**：展示景点的 FAQ 热度、AI 服务人次趋势、游客满意度趋势。

#### 模块一：服务人次

| 数据     | 说明                                           |
| -------- | ---------------------------------------------- |
| 总人次   | `summary.totalChats`                           |
| 趋势折线 | `trendList[]`：`time`（日期）、`count`（人次） |
| 时间范围 | 昨日(1天) / 近7天 / 近30天                     |

**接口**：`GET admins/stat/chat-trend/{attractionId}?days`

#### 模块二：热门问答

| 数据     | 说明                |
| -------- | ------------------- |
| FAQ 排行 | 问题文本 + 被问次数 |
| 时间范围 | 近7天 / 近30天      |

**接口**：`GET admins/stat/faq/{attractionId}?days`

#### 模块三：游客满意度

| 数据       | 说明                                          |
| ---------- | --------------------------------------------- |
| 满意度趋势 | 日期 + 平均满意度分数                         |
| 时间范围   | 昨日 / 近7天 / 近30天（与人次模块联动或独立） |

**接口**：`GET admins/stat/satisfaction-trend/{attractionId}?days`

**交互**：

- 时间范围切换后重新请求
- 折线图数据点可交互查看详情（日期、数值）

**需设计的状态**：各模块加载中、无数据、有数据、图表交互态

---

### 6.6 游客分析

**功能目的**：分析游客情绪趋势、关注焦点，并展示 AI 生成的运营建议。

#### 模块一：情绪趋势

| 数据         | 说明                             |
| ------------ | -------------------------------- |
| 情绪时序折线 | 正面 / 中性 / 负面数量随时间变化 |
| 时间范围     | 近7天 / 近30天                   |

**接口**：`GET admins/analysis/emtion-trend/{attractionId}?days`

#### 模块二：关注焦点卡片

| 数据                 | 说明                  |
| -------------------- | --------------------- |
| `positiveRate`       | 正面情感占比（%）     |
| `positiveRateChange` | 环比变化              |
| `changeLabel`        | 变化描述标签          |
| `topFocus`           | 高频关注点            |
| `topFocusRate`       | 高频关注点占比        |
| `worstFocus`         | 待改善关注点          |
| 时间范围             | 昨日 / 近7天 / 近30天 |

**接口**：`GET admins/analysis/emotion-focus-card/{attractionId}?days`

#### 模块三：AI 运营建议

| 数据         | 说明         |
| ------------ | ------------ |
| `summary`    | AI 分析总结  |
| `suggestion` | 具体运营建议 |

**接口**：`GET admins/analysis/ai-service-suggestion/{attractionId}?type=0`

**交互**：

- 折线图数据点可查看当日正/中/负面计数
- 建议区内容较长时需支持阅读（滚动等）

**需设计的状态**：各模块加载中、无数据（占位 `--`）、有数据、接口错误

## 七、跨页面子流程汇总

以下不限定 UI 形态（弹窗 / 底部 sheet / 独立页均可），但功能必须可达。

| 子流程           | 触发位置         | 核心功能                       |
| ---------------- | ---------------- | ------------------------------ |
| 选择景点         | 用户主页新建对话 | 搜索 + 列表 + 选择 → 开聊      |
| 评价             | 出游记录         | 星级(必填) + 文字(选填) → 提交 |
| 删除出游记录     | 出游记录长按     | 二次确认 → 删记录 + 删聊天     |
| 编辑昵称         | 个人中心         | 1~20 字符                      |
| 编辑年龄         | 个人中心         | 数字输入                       |
| 选择性别         | 个人中心         | 男/女/保密                     |
| 删除景点         | 景点管理         | 单条/批量二次确认              |
| 上传数字人视频   | 数字人管理       | 选视频 → 上传 → 预加载         |
| 测试视频台词输入 | 数字人管理       | 输入文本 → 生成 → 播放         |
| 删除知识库文档   | 编辑景点         | 二次确认                       |
| 权限引导         | AI 对话          | 引导去系统设置开麦克风/相机    |
